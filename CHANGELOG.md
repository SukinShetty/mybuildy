# Changelog

All notable changes to MyBuildy are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed

- **Recover damaged project lists safely** — an unreadable or damaged project list no longer silently starts a replacement project. Registry writes use a synced temporary file and rename, with a last-good backup. Startup offers an explicit backup restore naming its active project, or quits without starting a watch; damaged bytes and project memory are kept.
- **Stop when the watched window disappears** — the first observed gap now ends the watch and cancels in-flight work. Pick the window again to continue, including after minimization when the OS removes it from the capture list.
- **Restrict navigation and custom endpoints** — privileged windows may load only the bundled renderer document (or the configured development origin in development). Remote custom AI endpoints require HTTPS; loopback HTTP remains available for local servers.
- **Cancel pending paste dispatch on Stop** — pending native paste processes are stopped when the watch ends. Because a keystroke may already have reached the terminal, cancellation warns the user to check the terminal and does not reuse the same approval automatically.
- **Refresh a transitive dependency** — update the MCP SDK within Nemp's existing supported version range.

## [0.1.0] — 2026-09-23

First public release, source-available under the PolyForm Shield License 1.0.0. Windows installer and macOS DMGs (Apple Silicon and Intel) via GitHub Releases; Linux runs from source (untested).

The 0.1.0 downloads were rebuilt on 2026-10-10 from commit `6859353`, so they include everything below: Buildy's own voice (Female voice or Male voice), setting up with a local model instead of a cloud key, the request time-limit and paste-target fixes, and the Mac signing changes. (An earlier rebuild the same day, from `4937b8a`, did not include the local-model setup or those two fixes.) The version stays 0.1.0.

### Added

- **Set up with a local model, no key needed** — on the first-run *Your AI key* step, **Use a local model instead (Ollama or LM Studio)** lets you finish setup without a cloud key. MyBuildy looks for Ollama and LM Studio at their default addresses on this computer and shows which is running; if one isn't, it says how to install or open it, with **Check again**. The next step lists that app's models with the ones that can read images first, marks them, and checks the first one automatically; if none can read images, it tells you to download one. Watching still starts only once the model passes the vision check. The cloud-key path is unchanged.
- **Buildy's own voice** — without an ElevenLabs key, MyBuildy now speaks with Buildy's own voice, bundled in the installer and running on your computer: free, nothing sent anywhere. The voice order is ElevenLabs when you saved a key, otherwise Buildy's own voice, and the computer's own voice only if Buildy's voice can't run. Settings → Voice shows Buildy's voice as the default, with ElevenLabs (your own key) optional. Buildy speaks one sentence at a time and makes the next sentences while one plays. The voice model is downloaded from a pinned revision and SHA-256-checked (`npm run fetch:voice`), and loads once in a separate process, never in a window. (#2)
- **Female voice or Male voice** — Settings → Voice offers Buildy's voice as **Female voice** (the default) or **Male voice**, each with Play sample. The choice is saved at once and used from the next sentence, no restart. (#3)
- **No silence while Buildy's voice gets ready** — while a line waits for Buildy's voice to load, the robot shows he's getting ready to speak ("Getting my voice ready…") instead of looking idle. If the voice still isn't ready after 45 seconds, waiting lines are spoken in the computer's voice with a notice saying why, and Buildy's voice takes over as soon as it is ready. (#3)
- **The loop** — watch the terminal window an AI coding agent runs in, explain what happened in plain English, judge it against the stated goal (on track / drifting / blocked), and suggest the next prompt. Built and tested with Claude Code; with other terminal agents, watching works and paste is untested. MyBuildy runs the loop; the user approves each step.
- **Loop engineering blocks** — Goal, Memory, Verifier (a separate AI check, run only for prompts that were actually pasted), and Hand-off (when the model flags a decision for a person, it is handed back to the user instead of becoming a prompt). The hand-off card shows one short question for the user, never the checker's reasoning; answering or skipping it clears the mascot's alert for good. When the Verifier reports partial progress or a failure, the guidance never also says the goal is reached. Memory keeps durable facts only (features completed, decisions, blockers), never what the agent is doing at the moment.
- **Project system** — per-project memory namespaced under `userData/mybuildy-memory/<projectId>` (Nemp-backed, local JSON), with project switching and a one-time capture disclosure on first window pick.
- **Providers** — Anthropic, OpenAI and OpenRouter recommended, each with a short list of live-tested vision models (Show all for the rest); Google Gemini under Advanced, labelled "Not yet tested", plus Ollama / LM Studio / custom OpenAI-compatible endpoints. Live model lists fetched from the provider; no default model; a vision check gates watching until the chosen model proves it can read images.
- **Guided setup** — first launch walks through everything one step per screen: your AI key (with where to get one), a Suggested model checked automatically, on macOS the Screen Recording and pasting permissions (with a Restart button that resumes at the same step, and a skip option for pasting), four ready-made goals with a "Done when…" check, how to start your coding agent, and choosing its window. The line under the robot then always says the next step. Settings has **Run setup again**. The microphone is only requested the first time you click the mic.
- **The robot** — frame-by-frame animations that follow what is happening: idle with a blink, reviewing while the coding agent works, thinking while MyBuildy analyses, waving when a prompt is ready or it needs you, waiting while a decision card is open, a jump with sparkles when the Verifier passes, three jumps with confetti when the goal is complete, a sad face when blocked or a step fails, and running left or right while you drag it. Reduced motion shows still frames only.
- **Robot bar** — bright, high-contrast icons (orange on hover); Settings → **Robot size**, a slider from 60% to 200% with Reset (robot, bar, icons and text scale together), also Ctrl/Cmd + scroll over the robot, remembered across launches. **Hide** (eye icon) tucks the robot and its guidance away while it keeps watching — bring it back from the tray icon or Ctrl+Alt+B (Cmd+Option+B on Mac); a hand-off or alert while hidden arrives as a system notification. **Quit** (X) asks first, then shuts everything down.
- **Delete a project** — Set Goal → Manage projects lists every project with a Delete button. The confirmation names the project and needs its name typed; it removes only that project's memory. The last project, and the one being watched, can't be deleted; deleting the active one switches to another.
- **macOS: Dock, menu and Quit** — MyBuildy shows in the Dock with its icon and has a proper menu (About, Settings… Cmd+,, Quit MyBuildy Cmd+Q, Edit, Window). Quitting stops everything: watching, speech and every window. Clicking the Dock icon reopens the main window. The robot still floats over full-screen apps.
- **macOS: title bar** — the title and tabs stay clear of the red/yellow/green buttons at every window width.
- **Watching survives minimizing** — a minimized or hidden terminal keeps its watch; only a window that is really closed ends it. Settings → **Open log folder** shows a local log of when watching starts, pauses or stops and why, without window titles or screen text.
- **Turn-end detection** — while the agent works, only low-resolution local snapshots are compared (never sent anywhere); an analysis runs once the screen has been still for two 5-second checks after a change, or as a checkpoint after 3 minutes of continuous activity.
- **Paste into terminal** — one click pastes the suggested prompt into the watched terminal (Windows and macOS). MyBuildy never presses Enter: you read the prompt and run it yourself. If the prompt, project, watch or window changes before the paste, nothing is pasted and the panel says why; a failed attempt can be retried. A heuristic guard asks for a second click on prompts that look destructive.
- **Stop** — ends watching and cancels what is in progress: the current analysis, the Guidance screen's analysis and its auto-analysis timer, and a voice question at any stage (recording, transcription, answer). Nothing is captured or sent for them afterwards.
- **Separate projects** — goal and memory changes are saved only to the project they were started in. Switching projects clears the brainstorm conversation, guidance, the chosen window and the Guidance screen's state, and results that arrive for the previous project are discarded.
- **Usage limit** — a rolling hourly limit on AI requests (default 120, editable 20–600); watching pauses at the limit.
- **Voice guidance** — optional ElevenLabs voices, chosen by name, with a system-voice fallback; the mic button appears only when an ElevenLabs key is saved. Spoken answers can be selected and copied; a goal or prompt you ask for appears in its own box with its own Copy button, and a goal always ends with a "Done when…" check you can verify.
- **Mascot** — an animated, draggable, always-on-top companion with idle / watching / thinking / speaking states, plus the frosted-glass guidance panel.
- **Privacy wording** — Settings says where screenshots and prompts go: your provider, a custom endpoint by its address, or this computer for local models, and ElevenLabs whenever a voice key is saved. The one-time capture notice must be accepted before a window is captured for analysis or a voice question is uploaded; after Continue, the analysis resumes straight away. The README lists every data flow.
- **Strict provider checks** — each API key is only sent to its own provider over HTTPS, and a custom endpoint's key only to the endpoint it was entered for (a key saved by an earlier version stays unused until you confirm its endpoint in Settings). Provider errors and unreadable responses are shown as plain-English messages or short codes.
- **Security hardening** — API keys encrypted with Electron `safeStorage` (plaintext saving refused), sandboxed renderers (`contextIsolation`, no `nodeIntegration`), validated IPC payloads, strict CSP and navigation guards. Settings has a Delete-all-data button.
- **End-to-end test suite** — Playwright-driven Electron runs (`npm run test:e2e`, `npm run test:e2e:packaged`) in isolated throwaway profiles, covering launch, security invariants, secrets, and memory isolation, alongside the vitest unit suite.
- **Windows installer** — `MyBuildy-Setup-0.1.0.exe` built by a tag-triggered release workflow as a draft GitHub release with SHA256 checksums; the build fails if the tag, package and installer versions or file names disagree. The installer is unsigned in this release.
- **macOS DMGs** — `MyBuildy-0.1.0-arm64.dmg` and `MyBuildy-0.1.0-x64.dmg`, signed with an Apple Developer ID and notarized by Apple, attached to the same draft release and covered by the same `SHA256SUMS.txt`.
- **Mascot stays reachable** — a mascot dragged (almost) off every display slides back into view when the drag ends (all platforms).
- **Settings on first run** — the model list is only requested once an API key is saved, so a fresh install no longer shows a misleading "Your API key was rejected" (all platforms).
- **macOS permission checks** — Screen Recording is checked before watching (reported status plus a blank-frame check); Accessibility and Automation (System Events) are checked before pasting. Each missing permission is explained on the mascot and in the guidance panel, with a button that opens the right System Settings pane.

### Fixed

- **AI requests time out on time** — the 60-second limit (120 seconds for local models) used to stop counting once the provider started answering, so an answer that stalled halfway could keep MyBuildy waiting far longer. Now the limit covers the whole answer, for every provider (Anthropic, OpenAI, Google Gemini, OpenRouter, Ollama, LM Studio and custom endpoints). When it passes, the request is stopped, the robot and Guidance tab say the provider took too long, and Analyze Now and Stop work straight away; an Analyze Now pressed while waiting still gets its analysis. Brainstorm replies may take longer as long as they keep arriving. LM Studio and custom endpoints now get the local-model limit for screen analysis too.
- **Paste into terminal only reaches the window you picked** — the paste used to find its target by window title, so another window with the same title (two "Windows PowerShell" windows, or two Terminal windows on a Mac) could receive it. MyBuildy now identifies the picked window by its system window number — on Windows together with the program that owned it when you picked it — and checks it again right before pasting. If that window has closed or is no longer the same window, nothing is pasted and you are told so; the prompt stays on your clipboard. It still never presses Enter.
- **The guidance panel highlights what is being said** — a sentence is highlighted only while its audio plays, not while it is still being made. (#3)
- **The robot and the Guidance tab are one watch** — Analyze Now in the Guidance tab used to run its own capture and analysis while the robot stayed idle and still asked for a window. Now there is one watch: choosing a window in either place sets it for both; Analyze Now runs the watch's own analysis (even when paused or the screen is unchanged) and the robot shows it is working; the result shows on the robot, in its panel and in the Guidance tab; Auto in the Guidance tab is the robot's Pause/Resume; Stop from either place ends the watch everywhere. The robot never offers a prompt that was already pasted.
- **Analyze Now is never lost** — pressing Analyze Now while MyBuildy was already looking (for example right after Paste into terminal) answered "already running" and could then be dropped with no analysis. Now that look's result answers it, or a fresh look runs straight after; the Guidance tab says MyBuildy is already looking meanwhile.
- **The window picker lists only real windows, coding apps first** — the list is fresh each time a picker opens and refreshes every 3 seconds while open, so closed windows don't show; MyBuildy's own windows and overlays (such as the NVIDIA GeForce Overlay) are left out; terminals and coding apps (PowerShell, Windows Terminal, Command Prompt, Terminal, iTerm, VS Code, Cursor, the Claude app) come first.
- **Bring a hidden robot back from the taskbar or Dock** — on Windows, Hide now minimizes the robot so MyBuildy's taskbar button stays and clicking it brings the robot back; opening MyBuildy again from the Start menu, Applications or the Dock also brings it back. Hide says where to find him. Ctrl+Alt+B (Cmd+Option+B on Mac) still works.
- **What a first-time user ran into** — after Paste, the robot keeps saying "Pasted — now press Enter in your terminal" instead of "Waiting for Claude Code to finish"; when Paste is off, the robot says to copy from the panel and the panel says why Paste is off ("Use Copy instead"); a long analysis is no longer cut off (answer limit raised from 1500 to 4000 tokens), and raw JSON is never shown.
- **No silent voice switch** — when an ElevenLabs request failed (bad key, used-up credits, missing permission, voice not found, network), MyBuildy silently switched to the computer's default voice. Now the robot and Settings say which voice failed, which one is speaking instead and why, with an Open Settings button; the reason (never the key or the text) goes to the diagnostic log. A watch ending mid-sentence no longer cuts ElevenLabs off. The computer's voice is a natural female voice (Zira on Windows, Samantha on Mac), not Microsoft David unless it is the only one.
- **The robot's "!" badge** — on a slow machine, the robot's first watch status could arrive late and clear a "!" that a hand-off or analysis had already set. It no longer does.

### Changed

- **Mac install steps** — the README and Mac testing guide drop the Open Anyway / right-click / `xattr` steps, since the DMGs are Developer ID signed and notarized. Windows SmartScreen steps are unchanged.
- **Mac signing with the voice model inside** — the signed Mac build now signs correctly with the bundled voice model (`isbinaryfile` override, model folder left out of per-file signing), and the signed-build workflow launches the apps, including the Intel app under Rosetta, to prove the voice loads.
